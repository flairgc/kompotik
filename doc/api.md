# API основного сервера Kompotik

Статус: предлагаемый контракт v1 для обсуждения и последующего переноса в OpenAPI. Дата: 25 сентября 2026 года. Методы ещё не реализованы.

Основа: [архитектура v0.5](architecture.md), [функциональные требования](https://docs.google.com/document/d/13DhyOBaIGAJRgvpVTTC32wxpCtCYCFFowQn9RIn3KDU/edit), [нефункциональные требования](https://docs.google.com/document/d/1c5UXA0RfIJ75Z2sQTfz0E-spPfpsIqhiP_baDNj83vI/edit). Новые маршруты и поля — проектные предложения; открытые продуктовые правила не становятся утверждёнными из-за наличия метода.

Связанные документы: [экраны](user-interface.md), [БД](database.md), [внутренние сервисы](service-interfaces.md).

## 1. Общие правила

- Префикс внешнего API: `/api/v1`. JSON, поля `snake_case`, кроме ранее принятого `requestId` в ошибках. ID — UUID, версии — положительные целые, время — RFC 3339 в UTC, пояс — IANA ID. В примерах `card-1` и подобные обозначения заменяют реальные UUID.
- Все методы, кроме явно публичных, требуют входа. Пользователь берётся из сессии, `user_id` не принимается как указание владельца. Доступ проверяется для каждого вложенного ID, включая файлы, задания и кандидатов импорта.
- Веб: Secure/httpOnly cookie, защита CSRF и проверка Origin для изменений. Нативный клиент: Bearer access token, обновляемый refresh token. `device_id` идентифицирует установку, но не заменяет авторизацию.
- Списки: `limit` (предложение: 1–100, по умолчанию 30), непрозрачный `cursor`; ответ `{items, next_cursor}`. Фильтры перечислены для метода. Сортировка стабильна, последний ключ — ID. `null` означает явно отсутствующее значение; пропуск поля PATCH — не менять.
- Создание синхронной записи: `201`; чтение/изменение: `200`; удаление: `204`; принятое фоновое действие: `202` и `{job_id, resource_id}`. `GET jobs/{id}` возвращает состояние, не удерживает HTTP-соединение до готовности.
- На повторяемых создающих/командных запросах обязателен `Idempotency-Key`: регистрация, создание папки/карточки/импорта, публикация, применение импорта, копирование подборки, генерация и повтор задания. Ключ хранится по пользователю, методу и маршруту с хешем тела; повтор возвращает тот же результат. Для регистрации область ключа анонимная, ответ не содержит повторно используемых секретов. Вход не кешируется. Для учебных отчётов и событий ключом служит их собственный ID, сохраняемый вместе с историей.
- `PATCH`/`DELETE` изменяемых сущностей используют `If-Match: "<version>"`; несовпадение — `409 VERSION_CONFLICT`, отсутствие обязательной версии — `428 PRECONDITION_REQUIRED`. Учебные события передают ожидаемую версию в теле. Удаление связи «папка—карточка» само по себе идемпотентно.
- Прерывание HTTP-ожидания не отменяет запись. Фоновая отмена имеет отдельный метод. Срок хранения обычных ключей идемпотентности должен покрывать объявленный срок повторов клиента; после истечения сервер не обещает защиту произвольного старого запроса. Учебная дедупликация живёт вместе с принятой историей.

Ошибка: `{code, message, details, requestId}`. Основные статусы: `400` — некорректный синтаксис, `401` — нужен вход, `403` — запрещённое действие, `404` — нет доступного объекта, `409` — конфликт версии/ключа/состояния, `410` — устаревший курсор или снимок, `413` — превышен размер, `422` — неверные предметные данные, `429` — лимит, `503` — временная недоступность. Недоступный чужой приватный объект возвращает `404`. `details` содержит пути полей/ID проблемных записей, но не чужие данные. Для временных отказов сервер может передать `Retry-After`.

## 2. Вход, настройки и конфигурация

В таблицах пути указаны относительно `/api/v1`. «Вход» для GET означает query-параметры.

| Метод и путь | Назначение и вход | Ответ |
| --- | --- | --- |
| `GET /config` (публичный) | Совместимость клиента; query `platform`, `app_version`. | Минимальная версия, доступные функции, лимиты ввода и поддерживаемые версии контрактов. |
| `GET /languages` (публичный) | Опубликованные языки обучения. | Коды, названия, язык перевода, версия каталога. |
| `POST /auth/register` (публичный) | `{email, password}`. | `201 {user_id}`; вход выполняется отдельно. Подтверждение email пока не включено. |
| `POST /auth/login` (публичный) | `{email, password, device_id, platform}`. | Веб: сессионная cookie, профиль и CSRF-токен; native: профиль, access/refresh tokens и срок. Секреты не попадают в логи. |
| `POST /auth/refresh` | Native refresh token либо действующая web-cookie. | Обновлённая авторизация; для native — ротация refresh token. |
| `POST /auth/logout` | Текущая сессия. | `204`, отзыв сессии и очистка web-cookie. |
| `GET /me` | Текущий аккаунт. | Email, профиль, настройки, `settings_version`, текущая версия учебной политики. |
| `PATCH /me/settings` | `If-Match`; `interface_language`, `theme`, `timezone`, `cards_per_lesson`, `writing_enabled`, `intervals_seconds`, `failure_interval_seconds`, `preferred_audio_locale`. | Настройки и новая версия эффективной политики. Размер урока 1–8; интервалы положительные, непустые и возрастающие. |
| `GET /learning/policies/{version}` | Версия доступной пользователю политики. | Правила упражнений, оценивания, нормализации, интервалов и ограничения. Старые версии нужны для офлайн-отчётов. |

Новый снимок политики объединяет серверные веса/порог и настройки пользователя. Изменение темы не создаёт новую учебную политику. Уже назначенный срок повторения не переписывается при изменении настроек. OAuth, удаление/экспорт аккаунта и восстановление пароля добавляются после определения соответствующих сценариев.

## 3. Папки, карточки и каталог

| Метод и путь | Назначение и вход | Ответ |
| --- | --- | --- |
| `GET /folders` | Непосредственные дети: `parent_id` либо `roots=true`; язык, пагинация. | Папки с версией и вычисленными счётчиками уникальных карточек поддерева. |
| `POST /folders` | `{parent_id, name, source_label?}`. Язык наследуется от родителя. | Созданная папка. Корни создаёт сервер. |
| `GET /folders/{id}` | Заголовок и состояние папки. | Родитель, хлебные крошки, язык, название, версия, счётчики. |
| `PATCH /folders/{id}` | `{name?, parent_id?, source_label?}`, `If-Match`. | Обновлённая папка; циклы и смена языкового корня запрещены. |
| `DELETE /folders/{id}?recursive=true` | `If-Match`; явное удаление поддерева. | `204`; удаляются папки и связи, прогресс сохраняется. Для непустой папки без `recursive=true` — `409 FOLDER_NOT_EMPTY`. |
| `GET /folders/{id}/cards` | `recursive`, `status`, `hide_learned`, `q`, пагинация. | Уникальные карточки с прогрессом; `recursive=true` включает потомков. |
| `PUT /folders/{id}/cards/{card_id}` | Добавить доступную карточку того же языка; тела нет. | `200` — связь уже есть, `201` — создана. |
| `DELETE /folders/{id}/cards/{card_id}` | Удалить непосредственную связь. | `204`, независимо от наличия связи; другие папки не меняются. |
| `GET /cards` | Поиск: `language_id`, `q`, `sense_id`, `scope=public|mine|accessible`, пагинация. | Доступные готовые карточки; свои черновики доступны при `scope=mine`. |
| `GET /cards/{id}` | Полная карточка и текущий прогресс. | `Card`, текущая ревизия, доступные произношения. |
| `GET /cards/{id}/revisions/{revision}` | Историческое содержимое доступной карточки. | Неизменяемая ревизия для старого урока; доступ проверяется заново. |
| `GET /cards/{id}/related` | Другие значения той же лексической единицы, пагинация. | Доступные карточки с определениями; синонимы — отдельное будущее расширение. |
| `POST /cards` | Приватный черновик: `{language_id, sense_id, content, folder_id?}` либо `{language_id, new_sense, content, folder_id?}`. | `201 Card` со статусом `draft`. Ровно один из `sense_id/new_sense`. |
| `PATCH /cards/{id}` | Собственный черновик/новая черновая ревизия: `{content}`, `If-Match`. | Карточка с номером новой черновой ревизии. Владелец и смысл не меняются. |
| `POST /cards/{id}/publish` | `{draft_revision}`, `If-Match`; подготовить обязательное содержимое. | `202 {job_id, resource_id}`; после генерации публикуется ревизия. |
| `GET /catalog/collections` | Готовые подборки: язык, `q`, `level`, пагинация. | Название, цель, размер, версия. Наличие конкретной подборки зависит от подготовленного контента. |
| `GET /catalog/collections/{id}` | Описание подборки. | Метаданные, версия и доступные фильтры состава. |
| `GET /catalog/collections/{id}/cards` | `hide_learned`, пагинация. | Карточки подборки с прогрессом пользователя. |
| `POST /catalog/collections/{id}/copy` | `{collection_version, parent_id, name}`. | `201 {folder_id, card_count}`; копия состава целиком. При изменении версии — конфликт. |

`Card`: `{id, language_id, sense_id, visibility, owner_user_id, state, version, published_revision, draft_revision, content, progress}`. Для чужих общих карточек сведения о владельце не нужны. `content`: `{expression, translation, definition, examples[], morphology, accepted_forms[], article_forms[], pronunciations[], image_asset_id, dictionary_links[], source_refs[]}`. Примеры содержат исходную фразу и необязательный перевод; `article_forms` — `{id, article, written_form, grammatical_note?}`. Произношение: `{id, form_id?, locale, ipa?, asset_id, source_ref?, is_default}`. Отсутствие конкретного медиа представляется явно. Ключей S3 и служебных промптов в `Card` нет.

Одна готовая общая карточка на смысл/язык перевода; своих может быть несколько. API не разрешает пользователю менять общую карточку. Административные скрипты используют те же предметные проверки, отдельная публичная админ-панель здесь не проектируется.

## 4. Учебные данные и результаты

| Метод и путь | Назначение и вход | Ответ |
| --- | --- | --- |
| `GET /learning/queue` | `language_id`, `mode=initial|review`, `folder_id?`, пагинация. | Кандидаты: карточка/ревизия, прогресс, цикл, повторение и срок; серверное время и версия политики. Урок на сервере не создаётся. |
| `POST /learning/results` | Один завершённый локальный урок, структура ниже. | `201` при первом приёме, `200` при точном повторе; квитанция и актуальный прогресс всех карточек. |
| `POST /learning/events` | `{event_id, card_id, type: known|progress_reset, expected_progress_version, occurred_at}`. Только онлайн. | Сохранённое событие и актуальный прогресс/цикл. Повтор ID не применяет действие снова. |
| `GET /statistics` | `language_id?`, `date_from`, `date_to`. | Выучено/всего, по дням уникальные карточки первичного изучения/повторения/объединения и первые освоения; без рейтинга и ошибок. |

### Отчёт завершённого урока

| Поле | Смысл |
| --- | --- |
| `schema_version` | Версия формата отчёта, отдельно от API и политики. |
| `result_id`, `lesson_id`, `device_id` | ID неизменяемого отчёта, локального урока и установки. |
| `device_sequence`, `previous_result_id` | Монотонная последовательность завершённых уроков аккаунта на устройстве и предыдущий отчёт; `null` для первого. Нужны для упорядочивания отправки. |
| `language_id`, `mode` | Один язык и `initial` либо `review`. |
| `started_at`, `completed_at`, `timezone` | Фактическое время и пояс занятия; сервер отдельно фиксирует время приёма. |
| `policy_version` | Неизменяемый снимок учебных правил и настроек. |
| `cards[]` | Непустой массив без повторов ID, в пределах лимита политики. |
| `cards[].card_id`, `card_revision`, `learning_cycle_id` | Карточка, показанная ревизия и цикл обучения. |
| `cards[].base_progress_version`, `base_result_id` | Последняя подтверждённая версия и, если есть, предшествующий локальный отчёт этой карточки. Серверная версия не выдумывается клиентом. |
| `cards[].review_occurrence_id`, `base_schedule_version` | Для повторения — ID наступившего срока и версия расписания; для первичного изучения `null`. |
| `cards[].completed`, `exercises[]` | Завершённость назначенного плана и результаты упражнений. Частичный урок не принимается как завершённый. |

Каждое упражнение: `{type, first_answer_correct, hint_used, attempts, errors, pronunciation_id?, audio_asset_id?, form_id?, substitution_for?}`. Типы: `forward_far`, `forward_close`, `reverse`, `listening`, `writing`. Для аудирования обязательны ID произношения и неизменяемого аудиофайла. `substitution_for` объясняет замену недоступного типа. План доступности передаётся в `cards[].exercise_plan`: назначенные типы и пропуски `{type, reason}`; причины ограничены политикой (`writing_disabled`, `audio_unavailable`, `insufficient_choices`). Сервер сверяет план с ревизией, политикой и доступными данными, не принимает произвольное исключение сложных упражнений. Введённый текст хранить необязательно; это доверительная учебная статистика, не экзаменационный античит.

Сервер проверяет доступ, язык, ревизии, структуру плана, цикл, порядок и время. Сам рассчитывает рейтинг и срок. `score_after`/`learned`, присланные клиентом, не принимаются. Отчёт с неверной карточкой целиком отклоняется с `422 RESULT_INVALID`; уже принятый ID с другим телом — `409 IDEMPOTENCY_CONFLICT`.

Пример ответа (две карточки, одна из старого цикла):

```json
{
  "result_id": "result-1",
  "status": "accepted",
  "cards": [
    {"card_id": "card-1", "application": "applied", "progress": {"state": "reviewing", "version": 7, "learning_cycle_id": "cycle-1", "schedule_version": 3, "review_occurrence_id": "due-3", "next_review_at": "2026-09-28T12:00:00Z"}},
    {"card_id": "card-2", "application": "history_only", "reason": "old_learning_cycle", "progress": {"state": "new", "version": 9, "learning_cycle_id": "cycle-2", "next_review_at": null}}
  ]
}
```

Схема примера сокращает поля прогресса; полный `Progress` также содержит `score`, `interval_index`, `review_count`, `policy_version`, `learned_at`, `learned_source`, `last_result_at`. Рейтинг нужен локальному планировщику, но не выводится пользователю. Точный повтор возвращает сохранённую квитанцию применения и заново прочитанный актуальный прогресс; квитанция не меняет историю.

При сбросе `learning_cycle_id` меняется. Поздние отчёты старого цикла сохраняются только в историю. Уже выученная карточка не возвращается автоматически в обучение. Для карточки без записи прогресса предлагаются версия `0` и детерминированный исходный UUID цикла, вычисляемый из пользователя/карточки по общей схеме; первое изменение создаёт строку. Сброс всегда выдаёт новый UUID.

### Предложение по нескольким устройствам

Сервер принимает отчёты в порядке `device_sequence` для каждого устройства (начиная с 1); пропуск — `409 RESULT_PREDECESSOR_MISSING`, клиент сначала отправляет предыдущий. ID установки регистрируется при входе, последовательность сохраняется вместе с локальной очередью; после полного удаления локальных данных создаётся новый ID. Один `review_occurrence_id` засчитывается для расписания только один раз. ID следующего офлайн-повторения детерминированно выводится из цикла, предыдущего ID и `result_id`, поэтому цепочку можно проверить после доставки предыдущего отчёта.

Предлагаемая консервативная политика: выигравшая по порядку серверного приёма ветвь меняет прогресс; пересекающаяся ветвь сохраняется как `history_only` с причиной `schedule_conflict`, её потомки также не меняют расписание. Это новое предложение, а не уже согласованное правило архитектуры. Пределы допустимого времени/срока офлайна ещё нужны. Нарушение поддерживаемого формата или времени возвращает структурированную ошибку, очередь сохраняется для восстановления. Порядок двух отключённых устройств не объявляется точной хронологией.

Для двух первичных уроков одной карточки в одном цикле предлагается то же правило первого применения: если первичное изучение уже завершено, второй отчёт получает `history_only / initial_already_completed`. Он не начисляет рейтинг вторично и не назначает заново первый срок. Конкурентная отметка «Я уже знаю» также не отменяется запоздалым уроком: причина `already_learned`.

## 5. Офлайн-пакеты, медиа и синхронизация

| Метод и путь | Назначение и вход | Ответ |
| --- | --- | --- |
| `POST /offline-packages` | `{folder_id, additional_audio_locales?}`; создать снимок выбранного поддерева. | `202 {job_id, resource_id: package_id}`. Ревизии закрепляются после построения согласованного снимка. |
| `GET /offline-packages/{id}` | Статус/описание пакета. | Статус, размер, число карточек, `snapshot_cursor`, политика, manifest URL внутри API и срок доступности. |
| `GET /offline-packages/{id}/items` | Пагинация по закреплённому manifest. | Карточки/ревизии, прогресс, данные для вариантов ответов и перечень медиа с хешами и размерами. |
| `GET /media/{asset_id}/download` | Проверить права и получить файл. | `200 {url, expires_at, sha256, byte_size, mime_type}`. URL короткоживущий; кеш адресуется по `asset_id` и аккаунту. |
| `GET /sync/snapshot` | Первая страница полного доступного состояния; следующие — по `snapshot_id,cursor`. | `snapshot_id`, страницы папок, связей, карточек библиотеки, прогресса и настроек; в конце согласованный `sync_cursor`. |
| `GET /sync/changes?cursor=...` | Изменения после курсора. | Упорядоченные `changes`, `next_cursor`, `has_more`, `server_time`; изменения и tombstone для удалений. |

Снимок/manifest хранит ID версии файла, а не истекающий URL. Базовая загрузка включает изображения, выбранное произношение и аудио всех применимых форм с артиклями; дополнительные диалекты — по запросу. Клиент помечает пакет готовым после проверки файлов и хешей. Пакет не расширяет пул отвлекающих вариантов за выбранный учебный материал.

Курсор связан с согласованным порядком фиксации БД. Обычный `bigserial` сам по себе этим свойством не обладает. Полный снимок фиксирован между страницами; при его истечении загрузка начинается заново. `410 SYNC_CURSOR_EXPIRED` запускает полную загрузку, не удаляя локальную очередь результатов и черновики. Новое серверное состояние применяется как база, поверх которой клиент пересчитывает ещё не подтверждённые локальные отчёты.

Предложение: сервер хранит только временные manifests; список скачанных папок и фактическая готовность файлов принадлежат устройству. Отдельного серверного метода «сделать пакет готовым на телефоне» нет.

## 6. Импорт и фоновые задания

| Метод и путь | Назначение и вход | Ответ |
| --- | --- | --- |
| `POST /imports` | `{language_id, title, source: {type: "text", text}}`. | `202 {job_id, resource_id: import_id}`. Версия API пока не обещает файлы/URL/видео. |
| `GET /imports` | Собственные импорты: `status`, пагинация. | Название, язык, этап, время, ID активного задания. |
| `GET /imports/{id}` | Состояние и сводка анализа. | Версия, этап, количество кандидатов, предупреждения, ссылка на результат применения. |
| `GET /imports/{id}/candidates` | `resolution`, `hide_learned`, `q`, пагинация. | Слова/выражения, определения, вхождения, варианты смыслов/карточек, прогресс, состояние выбора. |
| `PATCH /imports/{id}/candidates/{candidate_id}` | `If-Match`; `{selected?, resolution?}`. | Кандидат с новой версией. `resolution` — выбранный доступный `sense_id/card_id` либо подтверждённое `new_sense`. |
| `POST /imports/{id}/selection` | `{action: "select_all"|"clear_all", filter?, expected_import_version}`. | Число выбранных и новая версия импорта; применяется ко всему фильтру, не только странице. |
| `POST /imports/{id}/apply` | `{expected_import_version, target: {folder_id}}` либо `{expected_import_version, target: {parent_id, name}}`. | `201 {folder_id, linked_count, created_card_ids, job_ids}`; генерации новых карточек идут в фоне. |
| `GET /jobs/{id}` | Доступное пользователю задание. | Тип, статус, этап, попытки, безопасная ошибка, результат/ID ресурса; `progress` только если измерим. |
| `POST /jobs/{id}/cancel` | Отменить незавершённое задание. | `200` если уже отменено, `202` если отмена ожидает исполнителя; завершённое — `409 JOB_ALREADY_FINISHED`. |
| `POST /jobs/{id}/retry` | Повторить окончательно неуспешную/отменённую операцию, если её предметное состояние это допускает. | `202`, тот же предметный ресурс и новая попытка/операция; карточка не дублируется. |

Изменение кандидата увеличивает также версию импорта, чтобы `apply` видел согласованный отбор. `apply` атомарно проверяет все выбранные смыслы, создаёт папку/связи/приватные карточки и задания. Повтор того же применения возвращает прежний результат; другое применение уже использованного импорта — `409 IMPORT_ALREADY_APPLIED`. Изменение отбора после применения запрещено. Для повторного использования нужно создать новый импорт либо работать с уже созданной папкой.

Для больших результатов лимит атомарного применения задаётся конфигурацией и сообщается заранее. Переход к многошаговому применению требует отдельного контракта; «атомарно» не обещается для неограниченной книги. Неоднозначные выбранные кандидаты без решения приводят к `422 UNRESOLVED_CANDIDATES`.

## 8. Что остаётся уточнить

До реализации нужны сроки хранения ключей/ревизий/снимков, допустимое офлайн-время, окончательные правила конфликтующих повторов и недостоверных часов, обязательность аудио, размеры текстов и пределы операций. OpenAPI должен содержать полные схемы и примеры для каждого метода; данный документ задаёт предметный контракт, но не заменяет машинную валидацию.
